# 商用切换待办清单（2026-04-10）

> [!WARNING]
> 这是 2026-04 的历史方案，包含已退役的身份、公开媒体和产品能力，不是当前上线清单。请勿复制其中环境变量或执行命令；当前合同见 `README.md` 的权威文档索引。

## 目的

这份文件只描述当前有效的两件事：

1. 第一阶段先用 `Wenwen-only` 做商用上线验证，还缺什么
2. 后续切到 `Wenwen + ComfyUI` 时，最小需要保留哪些开关和环境变量

不复述旧方案，不包含 `Liblib`。

## 第一阶段商用切换：`Wenwen-only`

### 当前目标

- `LLM_PROVIDER=wenwen`
- `GENERATION_ENGINE=wenwen`
- 先完成静态婚纱照生成链路的商用验证
- 暂不把 `Live Portrait` 作为第一阶段必上线能力

### 当前未完成项

#### 1. 存储未切商用

- 当前 `STORAGE_PROVIDER` 还是 `local`
- 商用必须切到 `s3` 或 `vercel`
- 需要补齐对象存储凭证、桶名、区域、公网回源和删除权限

#### 2. 视觉 QA 未切到商用要求

- 当前 `QA_REQUIRE_VISION=false`
- 商用要求应为 `QA_REQUIRE_VISION=true`

#### 3. 公网地址未切换

- 当前 `FRONTEND_BASE_URL` 仍是本地地址
- 当前 `WEBHOOK_BASE_URL` 仍是本地地址
- 商用要求改为公网绝对地址
- `CORS_ALLOW_ORIGINS` 需要包含 `FRONTEND_BASE_URL` 的 host

#### 4. 支付未补齐

- `CREEM_API_KEY`
- `CREEM_WEBHOOK_SECRET`
- `CREEM_PRODUCT_PACK_50`
- `CREEM_PRODUCT_PACK_120`
- `CREEM_PRODUCT_PACK_300`

#### 5. 基础设施未连通

- `DATABASE_URL` 当前不可达
- `REDIS_URL` 当前不可达
- `ARQ Worker` 未形成可用队列

#### 6. 上线范围要明确

- 第一阶段如果不包含 `Live Portrait`，当前不算阻塞
- 第一阶段如果必须包含 `Live Portrait`，当前就是功能缺口，不是配置问题

### 第一阶段建议执行顺序

1. 先切商用存储
2. 再改公网域名和 `CORS_ALLOW_ORIGINS`
3. 再补齐 `CREEM_*`
4. 再拉起可连通的 `Postgres + Redis + ARQ Worker`
5. 再把 `QA_REQUIRE_VISION` 设为 `true`
6. 最后跑严格预检和回归

- `ComfyUI` 改为负责：

## 关于 `Live Portrait` 的直白解释

`Live Portrait` 不是普通静态婚纱照生成，而是把一张人像做成动态视频的单独能力。

当前代码里：

- 当 `GENERATION_ENGINE=wenwen` 时，系统会判断 `Live Portrait` 不支持
- 这时调用 `/live_portrait/generate` 会直接返回 `503`
- 也就是说，`Wenwen-only` 现在只覆盖“静态图生成主链”，不覆盖“动态人像视频”

所以判断标准很简单：

- 如果第一阶段商用只卖静态婚纱照生成，这不算阻塞
- 如果第一阶段商用必须卖动态视频版 `Live Portrait`，那就不是配个变量能解决，而是需要改主链到 `ComfyUI`，或者单独实现 `Wenwen` 的动态视频方案
