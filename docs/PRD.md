# PRD：VowPic 海外 Web SaaS

> 版本：v4.1
> 日期：2026-07-13
> 状态：当前产品合同；实现状态必须以代码、测试和发布证据为准
> 当前架构：`docs/ARCHITECTURE.md`
> 当前生产收口计划：`docs/operations/vowpic-finite-production-closure-plan.md`
> 2026-07-10 商业闭环设计仅作历史决策追溯，不再作为当前运行拓扑权威。

## 1. 产品定义

VowPic 是面向海外用户的响应式 Web SaaS。用户通过浏览器登录、上传经授权的人像、选择婚纱影像风格、提交生成任务，并在质量检查通过后预览、购买和私密下载作品。

本 PRD 描述产品需求和验收边界，不表示所有商业闭环任务已经完成。代码构建通过、页面可打开或 mock 流程可运行，都不能替代真实 Google 登录、真实私有素材、真实异步生成、真实支付及正式域名验收。

## 2. 产品目标

### 2.1 用户目标

- 用清晰、可执行的提示完成合格人像上传。
- 在单人、本机双人或金婚重塑模式中完成作品创作。
- 在提交前明确看到积分成本、输入要求和失败处理规则。
- 在任务失败时获得明确状态和符合账本规则的积分释放或补偿。
- 仅由本人访问订单、素材、预览和最终交付物。

### 2.2 业务目标

- 建立可对账的积分购买、预留、扣减、释放和退款闭环。
- 建立可恢复的异步生成、质量检查、交付和清理链路。
- 以真实完成率、质量通过率、付费转化率和退款率衡量产品，而不是以页面数或接口数衡量。

### 2.3 非目标

- 不构建任何微信生态产品或登录、支付、分享分支。
- 不提供游客账户或公开密码登录。
- 不在当前公开版本中提供匿名远程合拍、Live Portrait、本地影楼推荐或线索 CRM。
- 不用静态样例、假商家、假支付、假生成结果或 Admin Probe 冒充普通用户主链路。
- 不在本阶段更换 FastAPI、Vue 3/Uni-app、PostgreSQL 或 Creem 技术边界。Redis 仅可作为可选缓存，不是生成队列或生产前提。

## 3. 用户与权限

### 3.1 普通用户

- 通过 Google OAuth 进入账户。
- 只能读取和操作自己的素材、订单、积分、购买和下载。
- 上传、生成、购买、删除和下载均要求可信身份。

### 3.2 管理员

- 使用 Google 账户和数据库中的管理员角色。
- 可执行受审计的订单、积分、支付和运行状态管理。
- 不得通过浏览器共享管理 token，也不得绕过普通用户权限模拟成功。

### 3.3 服务身份

- 网站后端、定时维护、对账和清理任务使用各自所需的最小权限凭据。
- 服务身份不得复用普通用户或管理员浏览器会话。

## 4. 公开创作模式

| 模式 | 输入 | 当前积分合同 | 说明 |
| --- | --- | ---: | --- |
| 单人 | 1 张人物照片 | 2 | 可叠加文本、服装或场景参考形成导演式输入 |
| 本机双人 | 同一浏览器上传 2 张人物照片 | 3 | 两位人物都由当前登录用户提交并授权 |
| 金婚重塑 | 2 张人物照片或适用的双人素材 | 3 | 面向父母、长辈或纪念合照的复古风格 |

积分值以版本化服务端定价快照为权威。前端展示不得自行覆盖后端定价；创建订单后也不得因后续调价改写历史成本。

匿名远程合拍不是当前公开模式。未来只有在完成受认证 Partner Invite、权限、素材所有权和双浏览器 E2E 后，才能按独立任务重新开放。

## 5. 核心用户流程

### 5.1 浏览与选择

1. 用户从首页或模板详情进入创建页。
2. 创建页展示模式、所需照片数量、积分成本、隐私提示和可选风格。
3. 没有可用模板或目录不可用时显示明确错误，不使用隐藏默认数据冒充成功。

### 5.2 登录

1. 用户选择 Google 登录。
2. Supabase 完成 OAuth 交换，业务后端验证身份并映射本地用户。
3. 登录失败、回调失效、用户被禁用或会话过期时，前端清理无效状态并要求重新登录。
4. 任何匿名指纹只可用于统计、限流或风险分析，不能拥有积分、订单或素材。

商业闭环最终身份合同要求短期、可撤销的本地会话和 HttpOnly Cookie；该能力属于后续身份任务。在其真实实现和验证前，不得在发布报告中宣称已达到最终会话合同。

### 5.3 上传与输入检查

1. 用户按模式上传 1 或 2 张照片。
2. 服务端验证格式、大小、像素、真实解码结果和素材所有权。
3. 服务端清除 EXIF/定位信息并安全重编码后再写入私有存储。
4. Gatekeeper 对人脸、清晰度、光照和输入安全进行检查。
5. 任一素材失败时整批失败；不创建订单、不预留积分，也不静默跳过失败文件。

私有素材、asset ID 和受控 Provider grant 属于最终商业闭环要求；必须由对应实施任务和真实存储测试证明，不得仅因 UI 已删除公开 URL 就视为完成。

### 5.4 创建与生成

1. 服务端重新校验身份、素材所有权、模式、模板、定价和可用积分。
2. 订单、积分预留和 generation job 在一个数据库事务中持久化；生成调度不依赖 outbox。
3. FastAPI 网站后端按 PostgreSQL 租约领取任务并调用唯一获批的生产图像 Provider。
4. 超时、拒绝、配额、无效响应和重复投递必须具有有限重试、幂等和可观察错误状态。
5. 后端领取或执行失败释放预留；Provider 或平台失败按账本规则退款或补偿，不能直接改写历史流水。

当前生产图像 Provider 仅为 Evolink；生成服务拒绝任何非 Evolink 配置且不存在隐式 fallback。遗留 outbox 表只保留下载审计或历史 schema 兼容用途，不参与生成调度。

### 5.5 质量检查与交付

1. Provider 输出先转存为私有候选素材，不能把 Provider URL 直接交给用户。
2. 候选结果必须通过结构化质量检查。
3. 质量检查异常不得按通过处理；修复有明确次数上限。
4. 预览水印失败不得回退交付未加水印原图。
5. 最终作品仅通过短期、绑定用户和订单的下载授权交付。
6. 删除请求必须可重试、可审计，直到存储确认对象不存在。

## 6. 积分、支付与退款

- 积分以不可变 ledger 为对账权威，余额只是快照。
- 普通生成使用预留、扣减和释放，不允许余额变负。
- Creem checkout、webhook、退款、部分退款和争议必须幂等处理。
- 未知支付事件进入隔离或人工核对，不返回默认成功。
- 卡号、CVV、银行数据和原始支付凭据不得进入本系统日志或数据库。
- 公开退款说明、支持入口和实际账本行为必须一致。

积分包、订阅和高风险支付能力只有在对应 feature flag、真实 Provider、对账和回滚门通过后才能启用。关闭期间公开 API 应 fail-closed，而不是显示可购买但实际不可用的占位入口。

## 7. 订单与状态

用户至少应能区分：

- 等待输入或输入被拒绝；
- 已接受、排队中、处理中；
- 质量检查或有限修复中；
- 可预览、可下载；
- 失败、退款/积分释放处理中；
- 已删除或保留期到期。

刷新、重复提交、网络中断和网站后端重启不得产生重复订单、重复扣费或重复 Provider 调用。历史订单可以保留旧模式元数据用于只读解释，但不能重新暴露已退役入口。

## 8. 页面与交互要求

### 8.1 必需页面

- 首页和模板浏览；
- 登录/注册引导（Google OAuth）；
- 创建与上传；
- 生成进度、预览与交付；
- 订单列表和订单详情；
- 账户、积分、购买、隐私、条款、退款和支持；
- 受角色保护的管理后台。

### 8.2 状态覆盖

每个关键页面必须覆盖加载、空数据、权限不足、输入失败、网络失败、服务不可用、重复提交、重试和会话过期。错误信息应提供可执行下一步，同时不得泄露 token、内部路径、SQL、对象 key 或 Provider 原始响应。

### 8.3 响应式与无障碍

- 支持桌面和移动浏览器，不能依赖原生 tab bar 或平台专属 API。
- 键盘导航、可见焦点、语义标签、对比度和错误关联达到 WCAG 2.2 AA 基线。
- 英文为默认语言，中文为可选语言；语言切换不能改变业务状态。

## 9. 已退役公开合同

以下旧入口必须由集中式、无数据库查询且无副作用的 router 返回 HTTP 410 和稳定错误码：

- 旧密码登录和旧用户 CRUD；
- 游客身份及账户合并；
- 旧直接积分增减/购买；
- 旧远程 session 创建、上传和绑定；
- Live Portrait；
- 本地影楼推荐；
- Leads/CRM。

退役 router 只能保存精确路径和统一错误合同，不能导入旧业务服务。删除旧实现不能让 410 静默退化为 404。

迁移、库存盘点、风控内容检测和冻结历史文档可保留相关术语，但不得被注册成公开产品入口。`users.openid` 仅可暂留为数据库内部 legacy alias，不得公开序列化或参与授权。

## 10. 安全与隐私基线

- 所有外部输入默认不可信，按格式、范围、权限和业务规则验证。
- 普通用户不得提交任意公网 URL 作为生产生成素材。
- 数据库访问参数化；上传防路径穿越、内容伪装和图片炸弹。
- 日志不记录 token、密钥、原图、支付凭据或不必要的个人信息。
- 状态变更接口校验 Origin/CSRF；生产 CORS 只允许精确 origin。
- 生产数据库 TLS 必须验证证书与主机名。
- 管理操作、积分调整、支付处理和删除操作保留可追踪审计证据。

## 11. 指标与可观测性

核心指标：

- Google 登录成功率和会话失败分类；
- 上传/Gatekeeper 通过率及失败原因；
- 订单接受率、队列等待时间、生成成功率；
- QA 首次通过率、修复率和最终失败率；
- 积分预留、扣减、释放、退款和对账差异；
- checkout、webhook、退款与争议处理状态；
- 私有素材删除延迟和失败重试；
- Preview 到购买、购买到私密下载的真实转化。

指标不得包含原图、完整 OAuth subject、支付凭据或可直接识别个人的敏感数据。

## 12. 验收与完成定义

### 12.1 本次 Web-only 清理验收

- 活跃前端、依赖和 manifest 无微信端构建或运行分支。
- 公开身份只保留 Google OAuth；无游客、密码或 OpenID 公开字段。
- 创建、支付和预览界面无远程 session、二维码、Live Portrait、推荐或 Leads 承诺。
- 所有列明旧路径由同一个 tombstone router 返回 410，且无业务副作用。
- 相关后端测试、前端类型检查、Web 构建和桌面/移动浏览器主流程通过。
- lockfile 与 package manifest 一致；无无效测试脚本、无调试残留。

### 12.2 商业闭环完成

只有获批实施计划中全部强制任务、真实外部服务集成、Preview 门、staged Production 门、正式域名门、回滚演练和 release bundle 都通过，才能称为“规划完整实现”或 `Production accepted`。

本地测试结果不可迁移为生产证据。正式结论必须绑定精确 source SHA、数据库 revision、API deployment、backend executor digest、feature-flag snapshot 和验收报告。
