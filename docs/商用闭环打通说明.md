# 商用闭环打通说明（执行版）

## 目标
- 在 `DEBUG=false` 下，服务以严格模式启动。
- 关键依赖缺失时直接失败，不允许“服务起来了但主链路不可用”。
- 支付、存储、内容安全、队列、ComfyUI 都进入统一就绪检查。

## 当前代码能力
- 启动阶段会先做商用配置校验，再做运行时就绪检查。`backend/app/main.py`
- 就绪检查覆盖：
  - `commercial_config`
  - `database`
  - `redis`
  - `task_queue`
  - `comfyui_runtime`
  - `storage_config`
  - `payments_config`
  - 可选 `storage_rw_probe`
- 运维接口：
  - `GET /api/v1/ops/readiness`
  - `GET /api/v1/ops/public_config`
- 商用主链路已固定为：
  - `LLM_PROVIDER=jiekou`
  - `GENERATION_ENGINE=comfyui`

## 直接执行命令

```bash
python backend/scripts/check_commercial_readiness.py
python backend/scripts/check_commercial_readiness.py --probe-storage
python backend/scripts/run_e2e_commercial_regression.py --base-url http://127.0.0.1:8000
```

## 环境文件约定
- `backend/.env`：仓库内本地开发默认配置，优先保证本地可启动。
- `backend/.env.example`：生产 / 联调模板，按商用严格模式填写。

## 严格模式下必须满足
- `DEBUG=false`
- `GENERATION_ENGINE=comfyui`
- `LLM_PROVIDER=jiekou`
- `STORAGE_PROVIDER=s3` 或 `vercel`
- `ALLOW_MEMORY_FALLBACK=false`
- `GATEKEEPER_ALLOW_WITHOUT_PILLOW=false`
- `QA_ALLOW_WITHOUT_PILLOW=false`
- `QA_REQUIRE_VISION=true`
- `COMFYUI_REQUIRE_STORAGE_DELIVERY=true`
- `SECRET_KEY` 已轮换
- `ADMIN_TOKEN` 已配置
- `PHONE_CRYPTO_KEY` 已配置
- `JIEKOU_API_KEY` 已配置
- `CREEM_*` 已配置
- `FRONTEND_BASE_URL` 为公网绝对地址
- `WEBHOOK_BASE_URL` 为公网绝对地址
- `CORS_ALLOW_ORIGINS` 包含 `FRONTEND_BASE_URL` 对应 host

## 外部依赖检查项
- Postgres 可连接
- Redis 可连接
- ARQ 任务队列可用
- ComfyUI 可访问且 workflow 与节点已就绪
- 对象存储可写、可删、可回源
- Creem 回调可回到公网后端地址
